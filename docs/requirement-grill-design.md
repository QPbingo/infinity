# requirement-grill Skill 设计规格

## 概述

`requirement-grill` 是一个自包含的需求澄清 skill，零外部依赖。用户安装即可使用，从模糊需求到经过五维度严苛拷问的清晰需求文档，一条龙完成。

## 定位与边界

- **输入**：用户自然语言需求（一句话到一段话）
- **输出**：Validation Brief（需求验证摘要文档）
- **终点**：清晰无歧义的需求文档
- **不包括**：方案设计、架构选型、实施计划
- **依赖**：零外部依赖，不依赖 grilling / superpowers 等任何其他 skill

## 触发词

`深挖需求` `需求拷问` `澄清需求` `grill需求` `requirement grill` `需求验证` `别急着做，先问清楚`

## 内部执行流程

```
用户输入需求
    │
    ▼
┌──────────────────┐
│ 1. 解析 & 复述    │  AI 用自己的话复述理解，确认没有理解偏差
└──────┬───────────┘
       │ 用户确认理解正确
       ▼
┌──────────────────┐
│ 2. 动态 Grill    │  AI 根据回答自动路由到需要深挖的维度
│                  │
│  ◉ 必要性 (必过)  │  ── 绿灯：有证据 / 不做的影响已明确 / 不是伪需求
│  ◉ 一致性 (必过)  │  ── 绿灯：不与已有系统冲突 / 不与其它需求矛盾
│  ◉ 边界   (必过)  │  ── 绿灯：范围明确 / 反场景已识别 / 极端输入已覆盖
│  ○ 优先级 (弹性)  │  ── 绿灯：must/nice 已区分 / 最小可行方案已识别
│  ○ 成功标准(弹性) │  ── 绿灯：验收标准可检验 / 成功指标有基线
│                  │
│  路由策略：       │
│  - 用户回答若已覆盖后续维度，自动绿灯跳过        │
│  - 发现矛盾或模糊，随时回到前面维度补充          │
│  - 锚点问题（每维度 2-3 个）确保不遗漏核心信号   │
│  - 锚点之外的追问由 AI 动态生成                  │
└──────┬───────────┘
       │ 退出条件：
       │  · 3 个必过维度绿灯全亮
       │  · AI 对「用户真正想要什么」信心足够高
       │  · 用户可随时喊停
       ▼
┌──────────────────┐
│ 3. 歧义扫描       │  专门检查残留的模糊词/多义词/隐含假设

       │
       ▼
┌──────────────────┐
│ 4. 产出 Brief     │  按五维度结构撰写摘要，请用户确认
└──────┬───────────┘
       │ 用户确认
       ▼
┌──────────────────┐
│ 5. 落盘           │  写入需求文档文件
└──────────────────┘
```

## 五个拷问维度

### 必过维度

**1. 必要性拷问（Existential Grill）**
- 绿灯条件：有证据支撑 / 不做的影响已明确 / 不是伪需求（XY Problem）
- 锚点问题：
  - 这个需求要解决的痛苦/机会，有数据或具体证据吗？
  - 如果不做，三个月后用户会因为缺少它而流失吗？
  - 这是问题本身，还是用户自己猜的解决方案？
- 核心目标：消除 XY Problem——用户要的是 Y，但真正需要解决的是 X

**2. 一致性拷问（Consistency Grill）**
- 绿灯条件：不与已有系统冲突 / 不与其它需求矛盾 / 团队能力可支撑
- 锚点问题：
  - 这个需求和你之前提的或系统已有的 X 是否矛盾？
  - 项目已有的架构约束、技术债务，这个需求兼容吗？
  - 团队能力和时间约束下，这个需求现实吗？

**3. 边界拷问（Boundary Grill）**
- 绿灯条件：范围明确 / 反场景已识别 / 极端输入已覆盖
- 锚点问题：
  - 什么场景下这个需求反而是有害的？
  - 最大并发/数据量/极端输入是什么？系统在边界处会怎样？
  - 如果输入是空的、错的、恶意的，预期行为是什么？

### 弹性维度

**4. 优先级拷问（Priority Grill）**
- 绿灯条件：must-have/nice-to-have 已区分 / 最小可行方案已识别
- 锚点问题：
  - 如果只能做一件事达到目标的 80%，你选哪件？
  - 有没有更简单的方式达到同样效果？
- 启用条件：需求涉及多个功能点，或用户明确要求排优先级

**5. 成功标准拷问（Success Grill）**
- 绿灯条件：验收标准可检验 / 成功指标有基线或可采集方案
- 锚点问题：
  - 你怎么判断这个需求做完了？验收标准是什么？
  - 如果上线后没人用，最可能的原因是什么？
- 启用条件：需求有明确的上线计划，或用户需要量化目标

## 退出机制

三层退出保障：

1. **绿灯底线**（防遗漏）：每维度锚点问题绿灯全亮，该维度方可通过
2. **信心阈值**（防过度追问）：AI 判断对核心意图的信心足够高，即使某锚点未严格全亮也可提前收束
3. **用户叫停**（兜底）：用户随时说「够了」「出 Brief」「跳过这题」

## 核心原则

- **深挖意图，消除歧义**：北极星指标是搞清楚用户到底想干什么，消除自然语言表达的模糊性
- **一次一问**：每轮只问一个问题，等待回答后再追问或切换维度
- **AI 动态路由**：不按固定顺序执行，AI 根据回答智能判断下一步
- **每个问题附带推荐答案**：降低用户回答成本
- **可独立使用**：不依赖任何其他 skill，装上就能用
- **职责单一**：只管需求澄清，不管方案设计
